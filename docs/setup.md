# Setup

[English](setup.md) | [日本語](setup.ja.md)

`runex init` wires runex into your shell. This page shows what it writes, what it never touches, the per-shell details, and how to check the result with `runex doctor`.

## Run `runex init`

`runex init` creates the config file, writes a shell-integration cache file, and appends one `source` line to your rc file. It asks before each write:

```
$ runex init
Create config at ~/.config/runex/config.toml? [y/N] y
Created: ~/.config/runex/config.toml
Install shell integration (cache at ~/.cache/runex/integration.bash, source line in ~/.bashrc)? [y/N] y
Wrote integration cache to ~/.cache/runex/integration.bash
Appended source line to ~/.bashrc

Next steps:
  1. Reload your shell: `source ~/.bashrc` (or `exec $SHELL`)
  2. Try `gst<Space>` — it should expand to `git status `.
  3. Add your own abbreviations: see https://github.com/ShortArrow/runex/blob/main/docs/recipes.md
  4. Verify any time with: `runex doctor`
```

Without a shell argument, runex picks the shell from `$SHELL` (or `$PSModulePath` on Windows). `runex init <shell>` targets one of `bash`, `zsh`, `pwsh`, `clink`, `nu` directly. `-y` answers every prompt with yes.

Open a new shell afterwards. The rc file is read at shell start, so the current session does not pick the integration up.

## Files `runex init` writes

Two files per shell. Both are rewritten every time you run `runex init <shell>` again.

**The cache file** holds the shell functions and the key binding. Its location follows `XDG_CACHE_HOME`; when that variable is unset, runex uses `~/.cache` on Linux and macOS and `%LOCALAPPDATA%` on Windows.

| Shell | Linux / macOS | Windows |
|---|---|---|
| bash | `~/.cache/runex/integration.bash` | `%LOCALAPPDATA%\runex\integration.bash` |
| zsh | `~/.cache/runex/integration.zsh` | `%LOCALAPPDATA%\runex\integration.zsh` |
| pwsh | `~/.cache/runex/integration.ps1` | `%LOCALAPPDATA%\runex\integration.ps1` |
| nu | `~/.cache/runex/integration.nu` | `%LOCALAPPDATA%\runex\integration.nu` |
| clink | `~/.local/share/clink/runex.lua` | `%LOCALAPPDATA%\clink\runex.lua` |

`RUNEX_CLINK_LUA_PATH` overrides the clink location.

Every cache file starts with a three-line header:

```bash
# runex-integration-version: 3
# runex-bin: /home/me/.cargo/bin/runex
# Generated by `runex init bash`; do not edit.
```

The `runex-bin:` line records the absolute path of the binary that ran `runex init`. The per-keystroke hook calls that path directly, so no `PATH` lookup and no version-manager shim runs on each key press. `runex doctor` compares the header against the running binary and reports a stale cache.

**The rc file line** is one block appended to the end of the file, marked with `# runex-init`:

| Shell | rc file | Appended line |
|---|---|---|
| bash | `~/.bashrc` | `[ -r '<cache>' ] && . '<cache>'` |
| zsh | `~/.zshrc` | `[ -r '<cache>' ] && . '<cache>'` |
| pwsh | `~/Documents/PowerShell/Microsoft.PowerShell_profile.ps1` on Windows, `~/.config/powershell/Microsoft.PowerShell_profile.ps1` elsewhere | `if (Test-Path '<cache>') { . '<cache>' }` |
| nu | `$XDG_CONFIG_HOME/nushell/env.nu`, or `~/.config/nushell/env.nu` | `if ('<cache>' | path exists) { source '<cache>' }` |
| clink | none; clink loads every `.lua` in its scripts directory | none |

## When the cache is regenerated

The cache file embeds the `[keybind]` settings. The `[[abbr]]` rules are not embedded: the hook reads `config.toml` on every key press, so a new rule works on the next key press without any regeneration.

| Event | Effect on the cache |
|---|---|
| `runex init <shell>` | Rewrites the cache and re-checks the rc file line. |
| `runex add`, `runex remove` | Rewrites every cache that already exists. A failed rewrite prints a warning and does not change the exit code. |
| `runex config reload` | Rewrites every cache that already exists from the current config file. Use it after editing `config.toml` by hand, then open a new shell. |
| `runex doctor` | Reports a stale cache. It never rewrites anything. |

`runex config reload` prints one line per shell:

```
$ runex config reload
bash: refreshed /home/me/.cache/runex/integration.bash
zsh: not installed (run `runex init zsh` to create its cache)
```

A config file that fails to load stops the command with exit code 1 and leaves every cache untouched. clink's lua file is not a cache in this sense: only `runex init clink` rewrites it.

## What `runex init` never does

- It never overwrites an existing config file. The file is created with `create_new`, so an existing file is left as is and reported.
- It never modifies lines you wrote. The rc file is opened in append mode and the block goes after the last byte.
- It never follows a symlink at the rc file path. On Unix the open uses `O_NOFOLLOW`.
- It never appends twice. If the `# runex-init` marker is already present, the rc file is left alone.
- It never appends to an rc file larger than 1 MB. Such a file is treated as if the marker were missing, and the append is refused.
- It never leaves a half-written cache. The cache is written to a sibling temp file, synced, and renamed into place.

These guarantees are pinned by tests in `runex/tests/cli_integration.rs`.

**To uninstall**, delete the block from `# runex-init` to the next blank line in the rc file, delete the cache file, and delete `~/.config/runex/config.toml` if you no longer want the config.

## Hand-managed dotfiles

`runex export <shell>` prints the same content `runex init` writes to the cache file, header included. Use it when your rc files are generated by another tool or synced across machines:

```bash
mkdir -p ~/.cache/runex
runex export bash > ~/.cache/runex/integration.bash
cat >> ~/.bashrc <<'EOF'

# runex-init
[ -r "$HOME/.cache/runex/integration.bash" ] && . "$HOME/.cache/runex/integration.bash"
EOF
```

`runex export` records the absolute path of the running binary, like `runex init` does. If the same rc file is used on machines where runex is installed at different paths, pass `--bin runex` so the script resolves runex through `PATH` at each key press.

`runex doctor` checks for the `# runex-init` marker and for the cache header. A rc file without the marker is reported as "marker missing". A rc file that still runs `eval "$(runex export bash)"` from a pre-0.1.16 install is reported as outdated: that form works but runs `runex export` at every shell start and skips the cache.

## Per-shell details

### bash

bash 4.0 or later is required. macOS ships bash 3.2; install a newer bash with Homebrew (`brew install bash`).

```bash
runex init bash
```

### zsh

```zsh
runex init zsh
```

### PowerShell

```powershell
runex init pwsh
```

Pasted text is inserted without expanding mid-paste. The integration reads PSReadLine's key queue to tell a paste from typed keys.

**PSReadLine must be loaded.** The integration registers a key handler with `Set-PSReadLineKeyHandler`. PowerShell 7 and Windows PowerShell 5.1 both ship PSReadLine, and the integration treats them the same. `Get-Module PSReadLine | Format-List Name,Version,Path` shows whether it is loaded and from where.

**The profile path differs between PowerShell 7 and 5.1.** `runex init pwsh` appends to the PowerShell 7 profile, `Documents\PowerShell\Microsoft.PowerShell_profile.ps1`. Windows PowerShell 5.1 reads `Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1` instead. To use runex from 5.1, copy the two-line block from the 7 profile into the 5.1 profile.

**Windows PowerShell 5.1 needs an execution policy that allows dot-sourcing.** The default `Restricted` policy blocks the `.ps1` cache file, so the profile line does nothing. Allow it with:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Under `AllSigned`, a newer PSReadLine picked up from `Documents\PowerShell\Modules` prompts "Do you want to run software from this untrusted publisher?" at every start. Choose `[A] Always run` once, or remove that directory from `$env:PSModulePath` so the bundled PSReadLine loads.

### Nushell

```nu
runex init nu
```

The source line goes into `env.nu`, which is also the file `runex doctor` checks for the marker.

### cmd (Clink)

```cmd
runex init clink
```

This writes `runex.lua` into clink's scripts directory and asks before overwriting a file that differs from the current output. Open a new cmd window afterwards.

clink reaches runex through a cmd.exe command line, which cannot carry `"`, `%` or `!` inside an argument. The lua file therefore sends the buffer hex-encoded. cmd.exe accepts at most 8158 characters after `cmd /c` (measured on Windows 11), so buffers above roughly 3900 bytes are not expanded and the trigger key inserts a plain space. The reasoning is recorded in [ADR 0003](decisions/0003-clink-hex-line-transport.md).

## Check the result with `runex doctor`

`runex doctor` validates the config, resolves every `when_command_exists` command, and inspects each shell's integration:

```
$ runex doctor
[OK]   config_file: found: ~/.config/runex/config.toml
[OK]   config_parse: config loaded successfully
[OK]   integration:bash: marker found in ~/.bashrc
[OK]   integration:zsh: rcfile not found at ~/.zshrc — assuming this shell is not in use
[WARN] integration:pwsh: marker missing in ~/.config/powershell/Microsoft.PowerShell_profile.ps1 — run `runex init pwsh`
[OK]   integration:nu: rcfile not found at ~/.config/nushell/env.nu — assuming this shell is not in use
[OK]   integration:bash:cache: cache up-to-date at ~/.cache/runex/integration.bash
[OK]   integration:zsh:cache: no cache at ~/.cache/runex/integration.zsh — run `runex init zsh` to install
[OK]   integration:pwsh:cache: no cache at ~/.cache/runex/integration.ps1 — run `runex init pwsh` to install
[OK]   integration:nu:cache: no cache at ~/.cache/runex/integration.nu — run `runex init nu` to install
[OK]   command:lsd: 'lsd' found (required by 'ls')
```

The rows that concern setup:

| Row | Meaning |
|---|---|
| `integration:<shell>` | Whether the rc file carries the `# runex-init` marker and the cache source line. A missing rc file counts as "shell not in use". A marker with a legacy `runex export` line is a WARN with the fix in the message. |
| `integration:<shell>:cache` | Whether the cache file exists, carries the current header version, and points at a binary that still exists. |
| `integration:clink` | Whether `runex.lua` on disk matches what this binary would write. Differs after upgrading runex. |
| `effective_search_path` (Windows only) | The PATH used to resolve `when_command_exists`. `+user` and `+system` count entries added from the registry when the inherited PATH was incomplete, which happens in cmd sessions started by clink. |

Every WARN names the command that fixes it. `runex doctor` itself never edits a file.

## Troubleshooting

The trigger key inserts a plain space instead of expanding:

1. Run `runex doctor`. Every WARN row names its fix.
2. **`runex hook` fails with `unrecognized subcommand`.** Another `runex` binary earlier on `PATH` is older than the integration expects. `which runex` and `runex version` show which binary answered; remove or upgrade the old one. The integration inserts a plain space on any hook error, which makes this look like a broken key binding.
3. **clink stopped expanding after a runex upgrade.** `runex.lua` is not refreshed automatically. Run `runex init clink` and open a new cmd window. `runex doctor` reports this as `integration:clink: outdated`.
4. **clink reports `command:lsd not found` although `lsd` is installed.** A cmd session started by clink can inherit an incomplete PATH. runex adds the registry's user and system `Environment\Path` entries; a directory outside both has to be added to one of them.
5. **pwsh: marker found but Space does nothing.** In order: PSReadLine is not loaded (`Get-Module PSReadLine` prints nothing), the 5.1 execution policy is `Restricted`, or `AllSigned` rejects the newer PSReadLine. The [PowerShell section](#powershell) has the commands for each.
6. **pwsh: `__runex_queued_key_count` is not recognized.** The cache file has two headers, usually because something concatenated `runex export pwsh` output with its own header. The interactive guard then skips the function definitions. Run `runex init pwsh` to rewrite the cache.
7. **A rule added by hand does nothing.** `[[abbr]]` edits work on the next key press. A `[keybind]` edit needs `runex config reload` and a new shell.
